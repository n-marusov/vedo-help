# Block-scoped `let` in try block inaccessible from finally block

**Date:** 2026-07-26 14:15
**Files:** frontend/src/stores/chat.ts
**Severity:** high

## Problem

`make build` failed because `vue-tsc --noEmit` reported:

```
src/stores/chat.ts:672:21 - error TS2304: Cannot find name 'completedSessionId'.
```

The `finally` block of `sendMessage()` referenced `completedSessionId`, which was declared with `let` inside the preceding `try` block, making it out of scope in `finally`.

## Root Cause

`let completedSessionId: string | null = null;` was placed at line 423, inside the `try` block (which started at line 385). The `finally` block at line 668 referenced `completedSessionId`, but `let` is block-scoped — `try` and `finally` are separate blocks, so the variable was not visible in `finally`.

This likely happened during a refactoring where the declaration was moved inside the `try` block without updating the scope, or where new code referencing `completedSessionId` was added to the `finally` block later.

## Solution

Moved the `let completedSessionId` declaration from inside the `try` block (line 423) to immediately before the `try` block begins (after `savePipelineState`). This makes it a function-scoped variable accessible in `try`, `catch`, and `finally`.

## Prevention

- When declaring a variable inside a `try` block that is also referenced in `catch` or `finally`, move the declaration before `try` with `let`.
- Run `vue-tsc --noEmit` (or the full frontend build) after any changes to complex `try`/`catch`/`finally` chains.
- TypeScript's block-scoping rules for `let`/`const` are strict; when in doubt, declare shared state variables at function scope.
