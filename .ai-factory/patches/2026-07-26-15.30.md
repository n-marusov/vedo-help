# e2e test uses POST instead of PUT for /api/admin/settings endpoint

**Date:** 2026-07-26 15:30
**Files:** frontend/e2e/document-reindexing.spec.ts
**Severity:** high

## Problem

E2E test `TC-REINDEX-001` in `document-reindexing.spec.ts` times out waiting for an assistant response after uploading a document and sending a query.

The test sends a settings reset request via `method: 'POST'` but the backend route `/api/admin/settings` only accepts `PUT`. Axum returns `405 Method Not Allowed`, and the test silently continues with stale settings from previous `admin-settings` tests.

## Root Cause

Two compounding issues:

1. **HTTP method mismatch (`document-reindexing.spec.ts:22`):** Test uses `method: 'POST'` for the settings endpoint. The backend registers only `put(settings_handlers::update_settings)` in `main.rs:476-478`. Axum returns 405 for unregistered methods. The test never checks `response.ok()`, so the failure is silent.

2. **Stale settings leak from `admin-settings` tests:** TC-SETTINGS-005 saves `llm_model=deepseek/deepseek-v4-flash`, `embedding_model=intfloat/e5-large-v2`, `llm_rerank_model=cohere/rerank-4-fast`. TC-SETTINGS-008b overwrites `llm_rerank_model=google/gemini-2.5-flash`. TC-SETTINGS-009 resets the UI form but does NOT click "Save Changes", so the backend still has the modified values.

The `document-reindexing` test tries to reset these to test-safe values, but the POST→405 failure prevents it.

## Solution

Changed `method: 'POST'` to `method: 'PUT'` in `document-reindexing.spec.ts:22` so the settings reset request reaches the backend correctly.

Also consider adding `response.ok()` verification to catch silent failures in the future.

## Prevention

- Always verify the HTTP method matches the backend route registration when writing e2e tests.
- When using Playwright `request.fetch()`, always assert `response.ok()` after write operations.
- After UI "Reset to Defaults" (TC-SETTINGS-009), verify via API that backend settings were actually reset, not just the form.
- Consider enforcing REST method consistency: create vs update should use POST vs PUT.
