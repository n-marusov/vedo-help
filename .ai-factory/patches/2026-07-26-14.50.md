# Use 127.0.0.1 instead of localhost in test DB URLs for Windows Docker compatibility

**Date:** 2026-07-26 14:50
**Files:** backend/tests/common/mod.rs
**Severity:** medium

## Problem

All 8 PostgreSQL-backed integration tests in the `integration` test binary failed with `PoolTimedOut` when connecting to `postgres://vedo:test-vedo-password@localhost:15432/vedo`. The 2-second `TEST_PREFLIGHT_TIMEOUT` was consistently exceeded.

```
thread 'test_collection_repo_native_uuid_bind' panicked at tests\common\mod.rs:71:9:
[FIX] test database connection refused at postgres://vedo:***@localhost:15432/vedo:
pool timed out while waiting for an open connection.
```

The 15 Chroma/LLM-only tests passed because they don't use PostgreSQL.

## Root Cause

On Windows with Docker Desktop (WSL2 backend), `localhost` resolves to IPv6 `::1` before IPv4 `127.0.0.1`. Docker Desktop does not properly forward IPv6 traffic from the host to containers on some configurations, causing TCP SYN packets to `[::1]:15432` to be silently dropped. The default TCP connection timeout for a dropped SYN on Windows is ~21 seconds (3×3s retries + 6s + 12s), far exceeding the 2-second `acquire_timeout` set on the test pool.

Rust's `TcpStream::connect()` / `tokio::net::TcpStream::connect()` iterates through resolved addresses sequentially. When `::1` hangs, the IPv4 `127.0.0.1` fallback never gets a chance within the 2-second window.

## Solution

Changed all hardcoded database URLs in `backend/tests/common/mod.rs` from `localhost` to `127.0.0.1`:

- `setup_test_db()` fallback URL: `localhost` → `127.0.0.1`
- `setup_test_config()` default URL: `localhost` → `127.0.0.1`

Added a comment explaining the Windows IPv6 rationale so future contributors don't revert it to `localhost`.

The `DATABASE_URL` environment variable override still works on any platform — this fix only affects the fallback paths.

## Prevention

- Use `127.0.0.1` (not `localhost`) in hardcoded connection URLs where Docker port forwarding is expected.
- Test connection strings on multiple platforms (Linux, macOS, Windows Docker) before merging.
- Consider adding a CI matrix job for Windows to catch cross-platform networking issues early.
